使用口径

Guide · 查看格式、算法与样例
用途
比较两段文字在字符层面需要的最少编辑次数，辅助定位改动。
输入格式
原文和新文各最多 240 个 Unicode 码点，允许一侧或两侧为空；原始 UTF-16 长度各最多 2000。CRLF 与 CR 转为 LF，其他文字、大小写和空白原样保留；不做 NFKC 或 NFC 归一化。
计算方法
Levenshtein 动态规划，每次插入、删除或替换成本均为 1，相同字符成本 0。等价最短路径优先相同/替换，其次删除，最后插入。按 Unicode 码点处理，不是字素，也不分析语义。
核对样例
默认“版本A待查”到“版本B已查”需要 2 次替换。ab 到 ba 在本工具中是两次替换，不把交换相邻字符视为一次操作。
边界与隐私
列出的原/新位置均从 1 开始；插入时原位置表示插入到该字符之前，可为末尾加一。换行和引号以 JSON 转义显示。字符最小改动不代表语义等价、质量或事实正确，输入不上传、不保存。
