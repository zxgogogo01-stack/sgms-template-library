# 109-stone-archway

## 模板定位

建筑档案、城市遗产、在地观察、修缮记录、建筑摄影与文化空间项目。视觉系统由石灰白纸面、矿物蓝结构线、陶土橙标记、硬边日影、石拱洞口、方位图和现场登记卡构成，不依赖外部图片也能形成完整高端界面。

## 后续 AI 接入规则（必须遵守）

本模板的 UI、响应式框架、组件层级、主题、交互、无障碍属性和安全输出已经完成。后续 AI **只替换变量与可见文字，不重建 UI，不改类名，不调整 DOM 结构，不改写 `archway.css` 或 `archway.js`**。新增档案、观察记录、构件影像或资料边界时，复制现有登记卡、正文段落、影像记录或规则组件，只替换内容与真实依据；不得在网站模板 UI 上再次浪费时间和 token。

## 文件

- `index.html`：石拱主视觉、四段现场登记、方位路线与工具入口。
- `article.html`：门外、拱券与门内现场笔记，含阅读进度、交接清单与复制。
- `tool.html`：建筑影像方位覆盖审计器，所有输入只在本地浏览器处理。
- `legal.html`：观察、尺度、专业判断、影像权利与修订边界。
- `404.html`：安全公开页检索与 noindex。
- `static/archway.css`：唯一视觉与响应式样式入口。
- `static/archway.js`：主题、菜单、进度、复制、影像审计与 404 路由。

## 变量

`%%LANG%%`、`%%SITE_NAME%%`、`%%BRAND_EN%%`、`%%SITE_DOMAIN%%`、`%%SITE_TAGLINE%%`、`%%SITE_DESC%%`、`%%CONTACT_EMAIL%%`

发布前替换全部变量，并复核标题、描述、canonical、Open Graph、邮箱、地点、构件名称、方位、影像编号、文件名、拍摄日期、尺度依据、隐私、来源、许可、专业评估边界与修订日期。

## 影像覆盖审计器规则

- 每行格式：`影像 ID | 构件名称 | 方位(北/东/南/西/细部) | 文件名`。
- 接受 2–100 个非空影像记录；总输入不超过 15000 个 Unicode 字符。
- 影像 ID 2–20、构件名称 2–60、文件名 5–100 个 Unicode 字符。
- ID、构件和文件名使用 NFKC、大小写与重复空白归一；ID 和文件名不可重复，构件按归一结果分组。
- 方位只接受北、东、南、西或细部；构件具备北、东、南、西才计为四向完整，细部不能替代方位影像，同一方位可有多张不同影像。
- 文件名不得包含 `/`、`\` 或 Unicode 控制字符，且必须使用 jpg、jpeg、png、tif、tiff 或 webp 扩展名；工具不接受文件路径。
- 界面最多展示前 40 条提示和 40 张影像，复制报告保留全部结果。
- 机械审计不读取文件，不验证照片内容、拍摄日期、尺度、EXIF、清晰度、真实性、建筑安全、病害、专业判断、隐私、来源或许可。

## 验收基线

- 五页各自只有一个 `h1`，1440×1000 与 390×844 均无页面级横向溢出。
- 移动目录首链聚焦，`Escape` 关闭并回焦；日照/阴影主题跨页保持。
- 正文进度到页尾为 100%；现场交接、资料边界摘要与完整覆盖报告可复制。
- 动态影像、提示和检索结果只使用安全 DOM 文本节点，不使用 `innerHTML`。
- 后续 AI 只能替换变量与文字，直接投入内容生产，不得重建模板 UI。
